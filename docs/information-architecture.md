# W8Pool 信息架构与数据流向

更新时间：2026-09-04

本文用于后续产品优化、代码维护和数据安全检查。核心原则是：岗位线索可以流动，个人判断必须跟随账户；访客模式只用于展示，不能进入真实账户数据。

## 1. 整体结构

### 工作台

- 首页
  - 岗位池统计
  - 任务概览
  - Robot 入口与最近运行
  - 便签 / 心情寄语
- 获取岗位
  - 我的岗位池
  - 智巡岗位 Robot（开发中）
- 共享岗位池
  - 群组岗位池
  - 社区岗位池（开发中）
- 我的任务
- 我的网申材料
  - 网申材料管理
  - 网申预填小助手（开发中）
- 个人中心
  - 账户备份与恢复
  - 云端历史与回滚
- 使用说明
- 版本日志

## 2. 数据分区

### 账户身份数据：私有

保存位置：D1 数据库。

- `users`
  - 用户 ID
  - 邮箱
  - 用户名
  - 展示名称
  - 密码哈希与盐值
  - 创建与更新时间
- `sessions`
  - 登录会话
  - Cookie 名称：`w8pool_session`
  - 有效期

数据边界：只用于登录、注册、鉴权。前端不能读取密码哈希。

### 个人岗位池：岗位本体 + 私有状态

保存位置：D1 数据库，前端本地缓存只作为临时缓存。

岗位本体保存在 `jobs.payload_json`，属于某一个 `job_pools`。

岗位本体字段：

- 基础识别
  - `id`：岗位 ID
  - `no`：池内编号
  - `companyName`：企业名称
  - `jobTitle`：岗位名称
  - `source`：来源
  - `importedAt`：导入时间
  - `createdAt` / `updatedAt`
- 岗位分类
  - `jobDirection`：岗位方向
  - `employmentType`：岗位性质
  - `industry`：所属行业主值
  - `industries`：所属行业数组
  - `companyType`：企业类型
  - `location`：工作地点主值
  - `locations`：工作地点数组
  - `educationRequirements`：学历要求
  - `graduationYears`：届次
  - `majors`：招聘专业
- 时间与链接
  - `publishedAt`：发布时间
  - `deadline`：截止日期
  - `applicationUrl`：投递地址
  - `announcementUrl`：公告链接
- 内容说明
  - `jobDescription`：岗位详情
  - `jobRequirements`：岗位要求
  - `hireProcess`：录用流程
  - `benefits`：福利待遇

用户私有状态保存在 `user_job_states`，同一岗位对不同用户可以有不同状态。

私有状态字段：

- `screening_status`
  - `to_review`：待筛选
  - `maybe`：待定
  - `selected`：决定推进
  - `skipped`：暂不考虑
- `application_status`
  - `pending`：待投递
  - `submitted`：已投递
  - `written_test`：笔试
  - `interview`：面试
  - `offer`：Offer
  - `rejected`：未通过
- `priority`：星级，0-5
- `applied_at`：投递时间
- `personal_notes`：个人备注
- `revision`：状态版本号
- `created_at` / `updated_at`

重要边界：筛选、投递进度、星级、备注都不是岗位本体，必须作为当前用户私有状态保存。

### 个人工作台文档：私有

保存位置：D1 `workspace_documents`，以前端 `useAppData` 同步。

文档键：

- `tasks`：任务
- `sticky-notes`：便签
- `profile`：网申材料档案
- `application-events`：个人操作记录
- `motto`：心情寄语
- `custom-tags`：快捷标签
- `job-note-tags`：岗位标签
- `app-view`：岗位池视图偏好
- `workspace-preferences`：工作台偏好

文档历史：

- `workspace_document_versions`：每次文档更新保留版本。
- `account_snapshots`：账户级快照。
- `user_job_state_versions`：岗位私有状态变更前版本。

### 群组岗位池：共享

保存位置：D1 数据库。

- `groups`
  - 群组 ID
  - 群组名称
  - 创建人
  - 创建 / 更新时间
- `group_members`
  - 群组 ID
  - 用户 ID
  - 角色：owner / editor / viewer
  - 加入时间
- `group_invites`
  - 邀请码哈希
  - 角色
  - 过期时间
  - 使用次数限制
- `job_pools`
  - `kind = group`
  - 绑定群组
- `jobs`
  - 群组池内共享岗位本体
- `job_events`
  - 共享岗位新增、编辑、删除、复制等池内动态

共享边界：

- 群组池岗位本体是共享数据。
- 成员可以从群组池把岗位纳入自己的岗位池。
- 纳入后会生成个人池副本，后续筛选、投递、星级、备注属于个人私有数据。
- 目前删除规则：只能删除自己添加到群组池的岗位；不能删除别人添加的岗位。

### 社区岗位池：开发中 / 演示

当前保存位置：前端静态演示数据 `src/data/communityPools.ts`。

当前特征：

- 用于展示未来社区岗位池的浏览、筛选、纳入思路。
- 当前不写入真实社区数据库。
- “纳入我的岗位池”等按钮以开发中弹窗说明未来行为。

正式上线后的预期边界：

- 社区岗位属于公共岗位线索。
- 用户纳入后生成个人副本。
- 用户私有筛选、投递、备注、标签仍只保存在本人账户下。

### Robot 巡检：开发中 / 演示

当前保存位置：前端静态演示数据 `src/data/robotJobs.ts`。

当前信息结构：

- 巡检设置
  - 企业性质
  - 城市
  - 届次
  - 类型
  - 检索关键词
  - 屏蔽词
  - 巡检频率
  - 巡检时间
  - 信息来源：待接入
- 巡检动态
  - 抓取条数
  - 抓取时间
  - 本次 / 上次巡检提示
- 待审核岗位
  - 新岗位标记
  - 抓取时间
  - 纳入我的岗位池
  - 淘汰

正式上线后的预期流向：

- 用户设置检索规则。
- AI 根据关键词和规则抓取公开岗位。
- Robot 产出待审核岗位。
- 用户点击“纳入我的岗位池”后进入个人池。
- 用户点击“淘汰”后移出待审核池，并用于后续去重。

### 网申材料管理：私有

保存位置：`workspace_documents.profile`。

基础信息字段：

- 姓名
- 年龄
- 手机
- 邮箱
- 所在地
- 政治面貌
- 民族
- 求职意向
- 头像
- 敏感字段展示开关

教育经历：

- 学校
- 学校标签
- 学位
- 专业
- 研究方向
- 起止时间
- 成绩 / 表现
- 备注
- 证书
- 自定义字段

通用材料：

- 荣誉奖项
- 常用素材库
- 自定义基础字段

按岗位类型维护的材料版本：

- 岗位类型
- 实习经历
  - 公司
  - 公司类型
  - 部门
  - 职位
  - 起止时间
  - 工作内容要点
- 项目经历
  - 项目名称
  - 项目类型
  - 成果
  - 起止时间
  - 项目描述
- 技能
  - 技能分类
  - 技能条目
- 校园 / 实践活动
- 证书
- 自定义模块
- 各模块自定义字段

### 网申预填小助手：开发中 / 私有草稿

当前主要使用本地页面状态，不直接写入外部网站。

信息来源：

- 目标岗位：来自我的岗位池编号。
- 个人材料：来自 `profile`。
- 模块版本：按岗位类型切换。

预期流向：

- 左侧选择材料模块与版本。
- 右侧生成可编辑预填草稿。
- 用户自行确认。
- 点击“开始写入”前应提示：仍需人工核对后再提交。

### 访客模式：隔离演示数据

保存位置：

- 初始数据：`src/data/previewSnapshot.ts`
- 浏览器本地：`preview:*`

访客模式数据包括：

- 虚构岗位
- 虚构任务
- 虚构群组岗位池
- 虚构池内动态
- 访客网申材料中的演示姓名等

隔离原则：

- 访客模式不读取 `account:{userId}:*`。
- 访客模式不写入真实 D1 账户数据。
- 访客模式的导入、复制、删除等操作只影响 `preview:*`。
- 新注册账户不加载访客数据。

## 3. 操作与数据变动矩阵

### 注册 / 登录

- 注册
  - 写入 `users`
  - 写入个人 `job_pools`
  - 消耗一个注册邀请码
  - 不创建岗位、任务、便签、网申材料、群组或演示数据
- 登录
  - 写入 `sessions`
  - 读取当前账户个人池和私有文档
  - 可能将旧本地缓存中的新增私有文档合并到云端

### 我的岗位池

- 手动录入岗位
  - 新增 `jobs`
  - 新增该岗位的 `user_job_states`
  - 新增 `job_events`
  - 不影响共享池，除非用户勾选同步群组池
- 编辑岗位本体
  - 更新 `jobs.payload_json`
  - 增加 `jobs.revision`
  - 新增 `job_events`
  - 影响当前池内的岗位本体
- 修改筛选状态
  - 更新 `user_job_states.screening_status`
  - 增加状态 `revision`
  - 变更前写入 `user_job_state_versions`
  - 不改共享池
- 修改求职进度
  - 更新 `user_job_states.application_status`
  - 写入 `application-events`
  - 不改共享池
- 修改星级
  - 更新 `user_job_states.priority`
  - 写入 `application-events`
- 修改个人备注
  - 更新 `user_job_states.personal_notes`
  - 不改岗位本体
  - 不改共享池
- 修改岗位标签
  - 更新 `workspace_documents.job-note-tags`
  - 属于用户私有数据
- 删除个人岗位
  - 删除 / 标记删除个人池中的岗位
  - 删除关联个人任务和个人操作记录
  - 不应删除共享池来源岗位
- 视图筛选 / 排序 / 分组 / 视图模式
  - 更新 `workspace_documents.app-view`
  - 属于用户偏好

### 批量导入

- 导入前校验
  - 读取 JSON 文件
  - 映射字段
  - 校验必填：`companyName` + `jobTitle`
  - 查重依据：企业名称 + 岗位名称
  - 同时检查已有岗位池重复和导入文件内部重复
  - 不写入数据
- 导入新岗位
  - 重复岗位直接跳过
  - 新增岗位写入 `jobs`
  - 新岗位写入 `user_job_states`
  - 新增导入事件
  - 导入前写入账户快照
  - 不覆盖已有岗位的筛选、进度、星级、备注或标签
- 全部导入
  - 重复岗位生成副本
  - 每个副本拥有新的岗位 ID 和编号
  - 私有状态只写到新副本上
- 同步汇入群组岗位池
  - 将本次实际导入成功的岗位复制到所选群组池
  - 写入群组池 `jobs`
  - 写入群组池 `job_events`
  - 若同步失败，个人池已导入内容不受影响

### 群组岗位池

- 创建群组
  - 写入 `groups`
  - 写入 `group_members`
  - 写入群组 `job_pools`
  - 创建群组邀请码
- 加入群组
  - 校验邀请码
  - 写入 `group_members`
  - 更新邀请码使用次数
- 私有岗位汇入群组池
  - 从个人池岗位本体复制到群组池
  - 去除个人私有字段
  - 写入群组池 `jobs`
  - 写入 `job_events`
  - 当前待优化：个人池与群组池之间缺少正式查重拦截
- 从群组池纳入我的岗位池
  - 从群组池岗位本体复制到个人池
  - 为当前用户创建新的 `user_job_states`
  - 默认筛选为待筛选、进度为待投递、星级为 0、备注为空
  - 不继承别人的私有判断
  - 当前待优化：群组池到个人池的查重需要更明确
- 删除群组池岗位
  - 仅添加者可删除
  - 标记 `jobs.deleted_at`
  - 写入删除事件
  - 不删除别人已经纳入个人池的副本
- 池内动态
  - 读取 `job_events`
  - 属于共享池协作记录

### 我的任务

- 自动进入任务页
  - 如果岗位未决定推进，会先询问是否标记为决定推进
  - 更新岗位私有筛选状态
- 新建任务
  - 写入 `workspace_documents.tasks`
  - 任务关联 `applicationId`
- 修改任务
  - 更新任务标题、类型、截止日期、备注、完成状态
  - 仍写入 `tasks`
- 完成任务
  - 更新 `done`
  - 写入 `completedAt`
- 任务聚合
  - 前端按公司 → 岗位 → 岗位下任务聚合展示
  - 不改变数据结构

### 网申材料管理

- 修改基础信息、教育、经历、项目、技能等
  - 更新 `workspace_documents.profile`
- 复制当前材料版本
  - 只读取 `profile`
  - 写入剪贴板，不改数据
- 新增 / 删除岗位类型版本
  - 更新 `profile.jobTypes`
  - 更新 `profile.variants`
- 与预填小助手联动
  - 预填小助手读取 `profile`
  - 页面内选择版本和编辑草稿

### 个人中心备份与恢复

- 下载账户备份
  - 读取当前账户私有数据
  - 下载 JSON 文件
  - 仅包含当前账户私有数据
  - 不包含群组岗位池中的共享数据
  - 备份带账户校验签名
- 从备份恢复
  - 校验当前账户
  - 分析新增 / 重复数量
  - 默认只恢复新增内容
  - 不覆盖已有数据
- 云端历史与回滚
  - 有操作时每 6 小时保留账户快照
  - 批量导入前保留快照
  - 回滚前保留快照
  - 回滚只作用于当前账户私有数据
  - 回滚不读取、不改动共享岗位池、成员或共享动态
  - 回滚不删除快照之后新增的岗位
  - 确认前展示回滚前后变化

## 4. 当前架构合理性检查

### 合理的部分

- 岗位本体与用户私有状态分离，这是保护多人协作数据的关键。
- 访客模式使用 `preview:*` 命名空间，与真实账户隔离。
- 新账户默认空工作台，不混入演示数据。
- 共享池的岗位被纳入个人池时生成副本，避免一个人的筛选、备注影响其他人。
- 云端文档有 revision，可减少多页面 / 多设备覆盖风险。
- 私有状态有 revision 和版本历史，适合后续做更细粒度的数据恢复。
- 回滚只恢复私有数据，不碰共享池，方向正确。

### 风险与待优化

- 个人池与共享池交互缺少完整查重策略。  
  建议：从个人池汇入群组池、从群组池纳入个人池时，都以“企业名称 + 岗位名称 + 城市 / 投递链接”作为可配置查重条件，先提示重复，再让用户选择跳过或生成副本。
- 岗位查重依据目前主要是“企业名称 + 岗位名称”。  
  建议：加入归一化规则，例如去除空格、统一括号、统一全角半角，并可辅助比较地点、公告链接、投递链接。
- `application-events` 是独立私有文档，不直接绑定 `user_job_states` 历史表。  
  建议：长期可将关键操作记录服务端化，减少本地文档同步失败导致操作记录不完整的问题。
- 任务依赖 `applicationId`，但岗位删除会牵动任务。  
  建议：删除岗位前提供影响预览：会删除多少关联任务、多少操作记录、多少标签。
- 社区岗位池和 Robot 目前是静态演示数据。  
  建议：正式开发时单独建表，不要复用访客演示结构，避免开发中功能进入真实数据链路时边界不清。
- 账户备份恢复与云端回滚是两个恢复体系。  
  建议：页面上持续区分“我手动下载的备份”和“系统自动保存的云端快照”，避免用户误解。
- 多设备冲突目前以 revision 阻止覆盖，但用户可见的冲突处理还不够完整。  
  建议：出现冲突时弹出“云端版本 / 当前版本”对照选择，而不是只提示同步失败。

## 5. 后续优化优先级

高优先级：

- 给共享池与个人池互相复制增加查重预览。
- 给删除个人岗位增加影响范围确认。
- 给多设备冲突增加可视化处理弹窗。
- 将个人操作记录进一步服务端化。

中优先级：

- 优化查重归一化规则。
- 给回滚快照增加筛选条件，例如按日期、操作类型、导入前、回滚前。
- 允许回滚时只选择某类私有数据，例如只回滚岗位状态、不回滚材料。

低优先级：

- Robot 和社区池正式上线后建立独立表结构。
- 为导入、复制、回滚等批量操作增加任务队列和进度条。
- 为账户备份增加备份内容清单页。
